# Mimic Content Workflow (Google Sheet driven)

Which API datapoint appears where in a mimic UI is decided in a Google Sheet, not in code.
The sheet is the single source of truth for mimic **content**: the designer fills in what each
component shows; a front-end developer (with an AI agent — see
[EXTENDING.md](./EXTENDING.md)) turns the filled sheet into code under
`src/modules/thrapp/mimics/modules/<module>/data/**`.

No code is generated by this pipeline. The scripts prepare and verify the sheet only.

```
schema.graphql ──┐
committed dhw/   ┤ pnpm generate-sheet-tabs ──► scripts/mimics/mimic-out/*.csv
thrusters data  ┘         (import into Google Sheet tabs)
                          │
                          ▼
                  Google Sheet workbook
                  ┌ Schema       read-only dictionary of every datapoint
                  │ Templates    read-only slots per component type
                  │ Instances    one row per entity to build (designer edits)
                  │ Controllers  named PID controller bundles (designer/dev edit)
                  │ Plan         formula-joined rows; designer fills values
                  │              export Plan (+ Controllers) as CSV
                          ▼
                  pnpm verify-plan <plan.csv> [controllers.csv]
                          ▼
                  front-end dev + AI agent implement it (EXTENDING.md)
                          ▼
                  pnpm typecheck && pnpm verify-plan --check <plan.csv>
```

## Files

| File | Purpose |
|------|---------|
| `generate-sheet-tabs.ts` | Rebuilds the CSVs below from `schema.graphql` + committed dhw/thrusters data. |
| `verify-plan.ts` | Validates a filled plan CSV against the schema catalog; `--check` also diffs it against committed mimic data. |
| `lib/` | Shared library (schema parser, TS data parser, canonical slot table). |
| `mimic-out/schema-catalog.csv` | Every datapoint in the API (`module, section, field, componentType, valveType, yardTag, technicalName, friendlyName`). The dictionary the designer picks from; search it by yard tag or friendly name. |
| `mimic-out/component-templates.csv` | Per component type: its slots (`slotId`, labels, expected datapoint types, required flag). Derived from the canonical table in `lib/templates.ts`. |
| `mimic-out/instances.csv` | The dhw/thrusters entities, for seeding the Instances tab. |
| `mimic-out/controllers-seed.csv` | Named PID controllers defined by dhw/thrusters, for seeding the Controllers tab. |
| `mimic-out/plan-seed.csv` | Worked example: the existing dhw/thrusters content in exactly the Plan format. Paste into the Plan tab instead of using the formula, or use it as reference. |

## Step 1 — Generate the CSVs

```bash
pnpm generate-sheet-tabs
```

## Step 2 — Build the Google Sheet

Create a workbook with five tabs and import the CSVs into them
(File → Import → Upload → "Replace current sheet" into a tab with that name):

| Tab | Source | Columns (row 1 = header) |
|-----|--------|--------------------------|
| `Schema` | `schema-catalog.csv` | A module, B section, C field, D componentType, E valveType, F yardTag, G technicalName, H friendlyName |
| `Templates` | `component-templates.csv` | A componentType, B typeLabel, C slotId, D slotLabel, E kind, F valueKind, G allowedFieldTypes, H required |
| `Instances` | `instances.csv` | A module, B folder, C key, D title, E componentType |
| `Controllers` | `controllers-seed.csv` | A module, B name, C pidType, D controllerField, E setpointField, F outputMinimumField |
| `Plan` | formula + hand-filled columns (below) | A–L formula, M–P filled by hand |

- **Schema** and **Templates** are read-only references.
- **Instances** is where new mimics are declared. One row per entity (a tank, valve, pump,
  sensor, circuit…). Adding a row automatically expands **Plan**.
- **Controllers** defines reusable PID bundles. Instances reference them by name.
- **Plan** holds one row per instance × slot. Columns A–L spill from the join formula;
  M–P are plain cells you fill by hand — typing there can never break the formula.

### Terminology

- **Component type** — the kind of UI component (Boiler tank, Pump, Connecting circuit, …).
  Designer-facing names live in the Templates `typeLabel` column (e.g. FreshwaterCircuit →
  "Connecting circuit").
- **Instance** — one concrete occurrence, identified by its `key` (usually the yard tag).
- **Slot** — a named input on a component type (`source`, `sensors.level`, `controls.valve`,
  `custom.circuitName`, …).
- **Datapoint** — an entry in the Schema tab; referenced in Plan by its `field` name
  (column C), e.g. `dhwTemperatureTank2`. Qualify with the module when taking a datapoint from
  another module: `dhw:adsorptionDelta`.

### The Plan tab

Paste this header into row 1 (A1):

```
module	folder	key	title	componentType	typeLabel	slotId	slotLabel	kind	valueKind	allowedFieldTypes	required	value	srcTitle	srcYardTag	notes
```

Put this formula in **A2** — it cross-joins Instances × Templates on componentType:

```sheets
=LET(
  inst, FILTER(Instances!A2:E, Instances!A2:A<>""),
  tmpl, FILTER(Templates!A2:H, Templates!A2:A<>""),
  ni,   ROWS(inst),
  nt,   ROWS(tmpl),
  ri,   TOCOL(MAKEARRAY(ni, nt, LAMBDA(r, c, r)), 1),
  ci,   TOCOL(MAKEARRAY(ni, nt, LAMBDA(r, c, c)), 1),
  keep, MAP(ri, ci, LAMBDA(r, c, INDEX(inst, r, 4) = INDEX(tmpl, c, 1))),
  fr,   FILTER(ri, keep),
  fc,   FILTER(ci, keep),
  MAP(fr, fc, LAMBDA(r, c,
    HSTACK(
      INDEX(inst, r, 1), INDEX(inst, r, 2), INDEX(inst, r, 3),
      INDEX(inst, r, 4), INDEX(inst, r, 5),
      INDEX(tmpl, c, 2), INDEX(tmpl, c, 3), INDEX(tmpl, c, 4),
      INDEX(tmpl, c, 5), INDEX(tmpl, c, 6), INDEX(tmpl, c, 7), INDEX(tmpl, c, 8)
    ))
  )
)
```

> Fallback: paste `plan-seed.csv` directly into the Plan tab instead of using the formula,
> then add rows by hand (copy an existing instance's block as template).

### Filling in the Plan tab (columns M–P)

What to enter depends on the row's `valueKind` (column J):

| valueKind | Enter in `value` (M) | Example |
|-----------|----------------------|---------|
| `field` | the Schema `field` name of the datapoint to show | `dhwTemperatureTank2`, `dhw:adsorptionDelta` |
| `customSource` | a technical-name slug for the component | `hot-water-tank-2` — plus `srcTitle` ("Tank 2") and `srcYardTag` (`1054`) |
| `literal` | display text | `Adsorption circuit` |
| `enum` | `Side` or `Top` (heat-exchanger port orientation) | `Top` |
| `controllerRef` | `@controller:<name>` naming a Controllers row | `@controller:pumpFlowController` |
| `instanceRef` | `@instance:<key>` referencing another instance | `@instance:adsorption` |

Leave a cell empty when a non-required slot isn't used. Use `notes` (P) freely.

## Step 3 — Export & validate

1. Export the Plan tab as CSV (File → Download → Comma-separated values); same for
   Controllers if you changed it.
2. ```bash
   pnpm verify-plan /path/to/plan.csv [/path/to/controllers.csv]
   ```
   This checks required slots are filled, every datapoint exists in the schema with the right
   type, and all `@controller:`/`@instance:` references resolve. Fix what it reports before
   handing off.

## Step 4 — Implement & verify

Hand the validated CSV plus [EXTENDING.md](./EXTENDING.md) to the front-end developer (and/or
their AI agent). After implementation:

```bash
pnpm typecheck
pnpm verify-plan --check /path/to/plan.csv
```

`--check` re-reads the committed mimic data and diffs it against the sheet: whatever the sheet
says must be exactly what the code does, and vice versa. Keep it green.

When schema, code, mimic data or design changes break this workflow, feed
